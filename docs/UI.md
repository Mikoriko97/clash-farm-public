# UI — дизайн-система HUD (затверджено власником 2026-09-04)

Макет: артефакт «Clash Farm HUD» (посилання в сесії). Тут — рішення, які кодуються.

Тема оформлення: поточний вигляд — Aaply Dark (`data-theme="aaply-dark"` на `<html>`, оверлей `web/src/themes/aaply-dark.css` поверх базових `hud.css`/`creator.css`/`city.css`; правила й перегляд на фейкових даних — `web/design-preview/README.md`). Нові екрани стилізувати змінними теми, а не власними кольорами.

Статус «Відпочив» (0026): чіп у правому верхньому куті (`RestedChip`: `😴 +10% XP · 2h 40m`, відлік за годинником сервера, зникає, коли час вийшов) і сповіщення після сну; дані з `GET /island` (`rested`) та відповіді `POST /house/sleep`; у моку чіп є завжди.

Мок-режим для перегляду дизайну: `?mock=1` в адресі (збірка з `VITE_MOCK_API=1` — на staging деплоїмо з ним явно, інакше коду моку в збірці нема) показує справжній Godot-світ і HUD на фейкових даних, позначка «Mock data» внизу; `?mock=nosession` — екран входу, `?mock=nochar` — створення персонажа. Код `web/src/mock/`, опис — `web/design-preview/README.md`.

## 1. Принцип

**Мова гри — англійська** (рішення власника 2026-09-28, ADR-024): усе, що бачить гравець, англійською; адмінка, документація й коментарі — українською. Примітки про відмінки в «Тексти й стани» нижче — історичні.
- Центр екрана — світ. Панелі лише в кутах, не перекривають персонажа й грядки.
- **Гра ногами.** Клік/тап по землі — персонаж іде. Клік по грядці — іде і виконує дію після приходу. У радіусі 1.5 м від обʼєкта Godot підсвічує його і шле `player_near`; React показує **одну** контекстну кнопку з найкращою дією (посадити / удобрити / зібрати / поставити декор). Клавіша `E` або тап; утримання 400 мс — вибір насіння.
- Відкрита шухляда або модалка → `set_mode(ui)`, світ не приймає кліки. Закрив → `walk`.
- Один акцент: золото — дія та ціни за кредити; рожевий — усе про CLASH; червоний — лише незворотне і помилки.

### Іконки і стани (2026-09-16, запит власника «довести UI до ідеалу»)
- Іконки хрому (панель інструментів, рядки меню, закриття, дім, щоденник, магазин) — один набір лінійних SVG `web/src/hud/Icon.tsx` (24 px, штрих 1.8, `currentColor`), емодзі там більше нема; іконки предметів — атлас з моделей, див. «Іконки предметів (UX етап 3)».
- Кожна кнопка має стани: наведення (підняття на 1 px + мʼяка тінь `--lift`), натиск, фокус (`--sun`), вимкнено (прозорість, без тіні). `select` у стилі пілюлі з власною стрілкою.
- Підказки `--ink-3` = 62 % молока (було 48 %, нижче AA). Кнопки-дії в рядках меню завжди золоті: контейнер рядка стилізується як `.menu-list > button`, щоб не перебивати `.price`.

### Екрани будівель міста (2026-09-20, демо на тестових даних)
- `web/src/city/`: `CityDoor` вирішує, що за дверима вітрини — демо-екран (`demoMode.ts`: dev або `?demo=1`) чи `ShowcaseSheet`. Каркас екрана: перемикач будівель → шапка (іконка, призначення одним реченням, мітки «Демо · тестові дані» / партнер / тип інтеграції) → плитки показників → графік → «твоя позиція» → вкладки дії → поле суми → рядки деталей → одна широка кнопка → підсумок дії → модель доходу проєкту й застереження.
- Спільні деталі (`parts.tsx`, `Sparkline.tsx`, `city.css`): `Stat`, `AmountField` (баланс, «Макс», вибір токена, сума в USD), `Details`, `Meter`, `Outcome`, `TokenMark`. Кольори за ролями: золото — дія і власні пули, рожевий — CLASH/clashSOL, зелений — дохід і позиція гравця, блакитний — графіки й партнерська інтеграція. Графік — одна серія 2 px з хрестовиною й підписом значення текстом; значення ніколи не фарбуються кольором серії.
- Реальні будівлі партнерів беруть цей каркас і деталі, міняючи джерело даних (SDK партнера, читання ланцюга сервером) — окремий ADR на кожну.

### Тексти й стани (UX етап 1, 2026-09-24)
- Назва предмета в реченні — відмінок: `accusative(id)` у `island/labels.ts` (жіночі на -а/-я → -у/-ю, чоловічі неживі без змін); заголовок плитки/рядка — `titleOf(id)` з великої літери; самі словники лишаються в нижньому регістрі.
- Помилки гравцю — лише через `api/humanError.ts`: коди сервера → свої тексти екрана, 502/503/504 → «сервер недоступний», обрив мережі → «немає звʼязку», сирий HTTP-текст ніколи не показується.
- Недоступна дія пояснює причину видимим текстом поруч («бракує N кр.», «ще N»), а не лише підказкою при наведенні; незавершене не малюється кнопкою.
- Незворотне поруч із головною дією (прибрати грядку чи лавку) — друге натискання протягом 3 с; «Вийти» — тиха вторинна кнопка.

### Іконки предметів (UX етап 3, 2026-09-24)
- Кожен предмет має картинку з 3D-моделі, а не емодзі: однаково на всіх ОС. Моделі — з гри (декор, інструменти, грядка) або з генератора `client/blender/crops/make_items.py` (урожай, страви, добрива, матеріали, пакетик, сувій) → `client/assets/items/*.glb` (у збірку гри не потрапляють: фільтр експорту «scenes»).
- Рендер: `client/tools/render_icons.gd` (потрібне вікно) — одне світло, ракурс 3/4 зверху-спереду, окремі ракурси в `VIEW` (поворот, нахил, крен). Довгі речі (сокира, кирка) — по діагоналі руків'ям униз-ліворуч, лезом угору-праворуч; «перед» моделі завжди до камери.
- Атлас: `client/tools/pack_icons.gd` — обрізка по альфі, клітинка 96² з полем 5 px, пакетик насіння = пакет позаду + урожай спереду з тінню, дозволи острова — один сувій з номером I–IV (бейдж у `ItemIcon`). Пише `web/src/hud/icons/items.{webp,css,ts}`; руками не правити.
- Web: `ItemIcon` — клітинка атласу 1.5em від шрифту слота (`.em`), тож розмір задає місце (плитка 39 px, рядок 36 px, контекстна кнопка 30 px); декоративна (`aria-hidden`), назва завжди поруч текстом; для id без клітинки — емодзі. Позиції — класи `.ii-<id>` у відсотках, без inline-стилів (CSP `style-src 'self'`).
- Перевірка: тест `itemIcon.test.tsx` (кожен предмет гри має клітинку, одна клітинка на id, позиції в межах), огляд усіх 67 у браузері в реальному розмірі.
- Новий предмет: модель (гра або `crop_items.py`/`crop_goods.py`) → `render_icons.gd -- --out=<тимч.> ` → `pack_icons.gd -- --raw=<тимч.>` → подивитися атлас очима.

### Звук і відгук (UX етап 2, 2026-09-28)
- Ассети — зі Freesound, усі CC0 (`docs/ASSETS_AUDIO.md`: джерела, автори, як замінити): `client/tools/build_audio.py` (Blender `aud` + numpy: обрізка тиші, шари, компресія, нормалізація, безшовні петлі) збирає WAV 44,1 кГц моно для 13 дій і 7 звуків інтерфейсу та ембієнт 32 кГц моно (острів 48 с — хвилі, материк 28 с — лісові птахи, печера 48 с — глуха атмосфера з краплями). Процедурний генератор `gen_sounds.mjs` лишився запасним (без `--force` не запускається: перезаписав би ці файли). Godot імпортує як QOA (≈4× менше в pck), ембієнти з `edit/loop_mode=1`.
- Світ (Godot, автолоад `Audio`, `scripts/audio.gd`): шини `SFX` і `Ambient` над Master створюються в коді; `play_fx` → кліп за таблицею `CLIPS` (`water` = добриво, `dig` = лопата, `interact` = клік) з висотою ±6 % на пулі з 6 плеєрів; ембієнт зони стартує на `set_zone`/`session_ready`, кросфейд 1,6 с на двох плеєрах. Тест `tests/test_audio.gd`.
- Кроки (`scripts/footsteps.gd`, компонент `Footsteps` у `Player.tscn` і `PeerAvatar.tscn`): на кожен дотик стопи в кліпах `walk_forward`/`walk_back`/`run_forward`/`sprint_forward` (моменти виміряно по кістках стоп: ліва нога на початку опори, права через півцикл) грається крок поверхні — `grass`, `dirt`, `stone`, `wood`, `sand`, `snow`, по 3–4 варіанти з висотою ±6 %, біг гучніший за ходьбу. Поверхня: `metadata/surface` колайдера під ногами (мости = `wood`) → постачальники групи `surface_provider` (`PlotGrid` = земля на ділянках, `MainlandTerrain.surface_for` дзеркалить шейдер землі `mainland_ground.gdshader`: урвище (нормаль.y < 0,72) — камінь, від `snow_line` + 1 м (42 м у матеріалі) — сніг, узбережжя нижче 0,5 м і піщаний біом — пісок, скельний біом — камінь, решта — трава; на острові піску й снігу нема: гравця тримають на плоскому верху, пляж за його краєм) → зона (печера = камінь, інакше трава). Свій персонаж грає без просторовості, чужі — `AudioStreamPlayer3D` (2 на аватар, створюються при першому кроці) лише в межах 22 м від камери. Усе на шині `SFX` (повзунок «ефекти»). Тест `tests/test_footsteps.gd`.
- Дощ, вітер і грім (`scripts/weather_audio.gd`, дочірній вузол `Audio`): дві петлі дощу (легка й сильна) і дві петлі вітру (бриз і шквал) на шині `Ambient` змішуються за `Weather.rain_level()` (дощ 0,55 — легка на повну, сильна чверть; гроза 1,0 — сильна на повну) і `Weather.wind_level()` (ясно 0,14 — тихий бриз, гроза 0,5 — шквал), рівні наздоганяють погоду 3 с, у печері ні дощу, ні вітру; спалах грози (`Weather.storm_flash`, не удар сервера по дереву) дає грім із затримкою 0,6–2,6 с.
- Листя (`WeatherAudio`): шелест (`ambient_leaves`, 40 с) іде за нормованою силою вітру (`leaves_weight`: штиль 0,15, помірний вітер 0,7 — повна, шквал не глушить) і множиться на «скільки листя в зоні» (`LEAVES_ZONE`: материк 1, острів 0,5, печера 0); дощ його не глушить. Поряд із бризом і шквалом (вони — гул, а це — яскравий шелест кронами).
- Ранок (`WeatherAudio`): `DayCycle` щокадру розсилає `set_hour` групі `DayCycle.CLOCK_GROUP`, до якої входить і звук погоди; петля ранкового хору птахів (`ambient_morning`, 36 с) наростає від 4:00 до 5:30, тримається на повну й стихає з 8:30 до 10:30 (`morning_weight`); дощ її заглушає (`dry_weight`), під землею (печера) тиша. Вночі й удень нічого не грає (день на острові — хвилі, на материку — лісові птахи ембієнту зони).
- Ніч (`WeatherAudio`): `DayCycle` щокадру розсилає `set_daylight` групі `NightLight.GROUP`, до якої входить і звук погоди; у сутінках (денне світло < 0,4) до ембієнту зони додається петля цвіркунів (`ambient_night`), на повну, коли світла майже нема, а зрідка (кожні 35–90 с, лише на повну ніч) — гук сови (`night_owl`). Дощ заглушає цвіркунів (повністю вже за рівня дощу 0,35), у печері ночі нема. Тест `test_footsteps`.
- Крафт: після успішного `POST /craft` (`useIsland.craft`, майстерня міста користується тим самим) React грає звук за родиною рецепта (`craftSound(output_item)` у `hud/sound.ts`: `dish_*` → `cook` — ніж, шкварчання й помішування; `decor_*` → `build` — пилка й молоток; `tool_*` → `forge` — два удари по ковадлу й шипіння гартування; `ingot_*` → `smelt` — міх, спалах печі, гудіння вугілля й шипіння гарячої сталі (рецептів зливків ще нема, звук чекає їх); решта → `craft`, наковальня з іскрою); помилка крафту — звичайний `error`. Тест `sound.test.ts` (кожен звук HUD має валідний WAV, крафт грає звук за родиною після відповіді сервера).
- Двері: `HouseNode` відчиняє (`door_open`) при вході й виході персонажа й зачиняє (`door_close`) через 0,25 с після того, як він зник чи вийшов; `Interaction` дзвенить дзвіночком (`door_bell`), коли найближчою ціллю стала міська будівля (підійшов до входу). Кліпи — у `Audio.CLIPS`; тести `test_house_flow`, `test_interaction`.
- Інтерфейс (React, `hud/sound.ts`): клік по будь-якій кнопці HUD, відкриття/закриття панелі, монети при продажу й купівлі, помилка, тост, фанфари рівня — WebAudio з файлів `web/public/audio/ui/`, контекст лише після першого жесту (автоплей), декодування з кешем.
- Гучність: ряд «Звук» у меню (`SoundRow.tsx`) — «ефекти» (світ + UI) і «ембієнт», квадратична крива (50 % ≈ −12 дБ), 0 = шина вимкнена, кнопка «Вимкнути/Увімкнути». Зберігає Godot (`user://settings.cfg` `[audio]`; `Quality` більше не стирає чужу секцію), web лише дзеркалить `sfx` з `volume_changed`. Міст: `set_volume`, `volume_changed` (docs/BRIDGE_PROTOCOL.md).
- Святкування рівня: стор фіксує `levelUp` при зростанні рівня в будь-якій відповіді сервера; `LevelUp.tsx` показує «Рівень N! Відкрилось: …» (предмети з `meta.level_min`, +1 грядка на парних рівнях) 7 с із фанфарами. Тости більшого розміру — `.toast.big`.

### Навчання перших хвилин (UX етап 4, 2026-09-28)
- Кроки: посадити → зачекати → зібрати → продати → купити насіння. Стан виводиться з відповідей сервера (`hud/tutorialSteps.ts`): грядки, інвентар (`crop_*`, `seed_*`), XP і рівень; клієнт нічого не зберігає (ADR-007) — прогрес живе в сесії (`useTutorial.ts`, зовнішній стор через `useSyncExternalStore`), галочки лише вмикаються (побачене не забувається), продаж = урожай в інвентарі зменшився, купівля = насіння побільшало. Гравець із XP ≥ 8 або рівнем ≥ 2 картки не бачить. Тест `tutorial.test.ts`.
- Картка «Перші кроки» (`Tutorial.tsx`): список із галочками, підказка поточного кроку з клавішею (на сенсорних екранах — словами, без клавіш), таймер до найближчого достигання від серверного годинника, «Пропустити» до кінця сесії; ховається за відкритою панеллю й у режимі будівництва. Крок «продай» без урожаю в руках веде назад до грядки. Потрібна кнопка пульсує (`.pulse`): контекстна — посадка/збір, «Інвентар» — продаж, «Магазин» — купівля. Остання галочка — привітання «Основи є!» з фанфарами.
- Поради на завісі переходу (`Curtain.tsx`, `TIPS`): по одній за кожну появу завіси, по колу (клавіші, добриво, ринок, камера, материк, грядки за рівні, «ніколи не просимо seed»).
- Серверні навчальні завдання з XP (ECONOMY_LAB §6) — окремо; зможуть живити ту саму картку.

### Створення персонажа (ADR-025)
- Показується одразу після входу, поки `/me` каже `nickname: null` (нові акаунти й наявні без ніка). Панель `web/src/character/CharacterCreator.tsx` стоїть справа (на телефоні знизу), а живий персонаж — у світі поруч: Godot ставить камеру впритул (`camera_preview`), персонаж дивиться в неї, стрілки ◀ ▶ повертають його, кольори змінюються на ходу (`player_look`).
- Нік: 3–16 символів, латиниця/цифри/`_`; форму перевіряє клієнт одразу (`character/nickname.ts`), вільність — сервер із затримкою 450 мс (`useNameCheck`). Кнопка «Start playing» ввімкнена лише коли сервер сказав «вільний». Нік не змінюється (ADR-025).
- Вигляд: вкладки Body (чоловіче/жіноче тіло, статура Average/Slim/Sturdy, шкіра, сорочка, штани, взуття), Hair (зачіска + колір), Face (обличчя, борода, окуляри), Hat, Outfit (вбрання + колір); «Random look». На вкладках голови камера наближається до обличчя (`camera_preview focus=head`; для Body й Outfit — весь зріст). Таблиці кольорів і частин — `character/palette.ts` (сервер знає лише індекси).
- Поки триває створення: режим `ui` (світ не реагує), гарячі клавіші HUD вимкнені, HUD не показується. Нік з'являється в чипі профілю замість гаманця й над головою для інших (`presence`).

## 4. Зміни в коді після «ок»
- **Bridge** (`shared/bridge-protocol.json`): Godot → React `player_near { kind: "plot"|"decor_slot"|null, idx, distance }`; React → Godot `walk_to { plot_idx | slot }`, `highlight { kind, idx | null }`.
- **Godot**: клік по землі → рух до точки (наявні анімації walk/idle), радіус взаємодії, підсвітка, камера за персонажем з орбітою і зумом, джойстик як TouchScreen-контрол у React (Godot отримує вектор через міст).
- **React**: `web/src/hud/` замість `IslandPanel`; `useIsland`/`usePurchase` без змін. Одна кнопка «Підключити гаманець» зі списком (групи Solana / EVM) замість ряду кнопок.
- Сервер не змінюється: позиція персонажа — лише клієнт, усі дії ті самі ендпоінти.

## 5. Рішення власника (2026-09-04)
1. Стиль — скло; на слабких GPU автоматичний fallback на мʼякий непрозорий.
2. Баланс CLASH з гаманця показувати лише коли він > 0 (read-only RPC).
3. Новачок: стартові культури в інвентарі + невелика сума кредитів (`economy.starter_credits`), щоб пройти цикл без буста. Числа — в ECONOMY §2.
4. На ПК блок WASD не показувати: керування інтерактивне, клавіші підписані на кнопках інструментів.
