# Материк — дизайн-документ (Фаза 2), v1 2026-09-08

> Статус: припущення П1–П7 і питання §12 вирішено власником 2026-09-08 (див. §2 і §12; ADR-019). Усе інше випливає з уже прийнятих рішень (`ARCHITECTURE.md`, `ECONOMY.md`, `PLAN.md` «Фаза 2», ADR-012/016/017, ескіз присутності 2026-09-05).

## 1. Навіщо

Острів — особиста ферма і петля «посадив → зібрав → скрафтив → продав». Материк — спільний світ, де гравці бачать один одного, добувають те, чого нема на острові, досліджують і заходять у місто, де стоять будівлі партнерських проєктів: стейкінг, свопи, пули ліквідності. Мета власника: гравець має хотіти сюди заходити не лише за умовами стейкінгу, а й за грою.

Принципи (ті самі, що й на острові):
- Сервер авторитетний. Клієнт лише просить і малює.
- Нуль кастодії. Будівлі партнерів не тримають токени гравця: дії відбуваються в гаманці гравця через SDK партнера, сервер лише читає ланцюг.
- Усе економічне — ледж, капи на день, `settings`.
- Godot — лише вʼю: терен, персонажі, ефекти. Уся логіка місця, ресурсів і присутності — на сервері.

## 3. Карта

```
        Північ (ліс, N–NW)                        Гори (E–NE)
   ┌─────────────────────────────────────────────────────────────┐
   │  ~ ~ ~ Темний ліс ~ ~ ~        ▲▲ Скелі ▲▲   ⛏ шахти        │
   │   гриби, деревина (дуб/сосна)   руда, камінь  ▲ печера #1   │
   │              Руїни маяка (орієнтир)            ▲▲▲          │
   │  Луки (W)                 ┌─────────────┐        Каньйон     │
   │   трави, квіти            │   МІСТО     │  ▲ печера #2      │
   │   ферма-музей             │  (D ≈ 300 м)│                   │
   │                           └──────┬──────┘  Озеро / річка (глина, риба пізніше)
   │   Болото (SW)                    │ дорога                     │
   │    очерет, рідкі гриби      Причал (S) ⛵ → острів            │
   └─────────────────────────────────────────────────────────────┘
        Південь: узбережжя, пляж, стартова точка
```

Зони і що в них:

| Зона | Площа (П1) | Ресурси | Особливе |
|---|---|---|---|
| Місто | круг D ≈ 300 м у центрі | — | будівлі партнерів, ринок, майстерня, ратуша, памʼятники, дошка сезону |
| Причал і пляж | смуга 80 м на півдні | мушлі (косметика) | точка входу, туторіал материка |
| Луки | ~0.15 км² захід | трави (5 видів), квіти | ферма-музей: «як було на острові», орієнтир |
| Ліс | ~0.3 км² північ/північний захід | деревина 2 видів, гриби, ягоди | темний ліс глибше: рідкісні гриби, вовки як перешкода (без бою: лякають — персонаж біжить) |
| Гори | ~0.2 км² схід | камінь, мідь, залізо | шахти = відкриті вузли; печери = окремі сцени |
| Печери (2–3) | окремі сцени 100–200 м | кристали, рідкісна руда | темно, ліхтар обовʼязковий, обмежений час за **ліхтарним маслом** (рішення власника: масло крафтиться з соняшника — потрібна культура соняшника в каталозі) |
| Річка/озеро | центральна вісь схід→південь | глина, пізніше риболовля | мости = орієнтири |
| Болото | ~0.08 км² південний захід | очерет, торф | повільний рух, рідкісні гриби |

Дороги зʼєднують причал → місто → ліс/гори; на дорогах швидкість +25 % (лише вʼю-ефект на клієнті, сервер перевіряє максимальну швидкість з цим бонусом).

## 4. Дослідження

- **Туман карти**: карта 1 × 1 км відкривається по клітинках 64 м, коли гравець там побував (сервер зберігає бітову маску відкритих чанків, 256 біт).
- **Орієнтири** (12–20 штук: маяк, руїни, старий млин, кістяк корабля, статуя, водоспад): перше відвідування = XP + запис у «Щоденник дослідника» + один рецепт або косметика. Сервер зараховує при `POST /mainland/discover { landmark }`, перевіряючи, що останнє відоме положення гравця (з присутності) в радіусі 15 м.
- **Щоденні експедиції**: 3 завдання на день («зруби 10 сосен у Темному лісі», «знайди 5 грибів на болоті», «відвідай маяк») — XP і міські кредити; замість грінду одного вузла. Ті самі денні капи.
- **Сезонні події**: гроза на материку валить дерева (як блискавка на острові) — спільна для всіх, вузли зʼявляються на 30 хв; метеорит у горах — кристали.

## 5. Ресурси поза містом

- Вузли **спільні**: кожен вузол (дерево, жила, кущ) має `hits_left` і `respawn_at` спільні для всіх гравців; хто вдарив — той отримав. Респаун 10–60 хв залежно від рідкості. Вичерпаний вузол зникає і повертається **на іншому місці** свого чанка (запит власника 2026-09-30): запікання резервує для кожного вузла до двох запасних точок (`alts` у `shared/mainland_nodes.json`, ≥ 6 м від дому й одна від одної, поза іншою флорою), а лічильник `respawns` (0024) росте разом з вичерпанням — вузол стоїть на `[дім, alts…][respawns mod (1 + alts)]`. Позицію завжди рахує сервер (`NodeSpec::at`), клієнт лише ставить те, що прийшло у вікні чанків; reach-перевірка гатеру міряється до поточної точки.
- **Особисті денні капи** на кожен ресурс (як `gather_max_per_day`): 60 ударів звичайних, 20 рідкісних, у settings.
- **Інструменти (П7)**: сокира/кирка з міцністю 100 ударів; крафт з деревини + руди в майстерні міста; ремонт за матеріали. Без інструмента — половина видобутку. Це головний sink матеріалів разом із будівництвом.
- **Рідкісні вузли** зʼявляються випадково в зоні (сервер, seed по годині як погода) — стимул ходити, а не стояти.
- Захист від ботів: ті самі капи, rate-limit, перевірка положення за присутністю (не можна вдарити вузол за 200 м), і `events` для аналітики.

## 6. Економіка материка (усе в межах `ECONOMY.md`)

Градація (П4) — один принцип для культур, матеріалів і рецептів: `tier` 1–4 у каталозі; ціна, XP і кап на день ростуть з тиром, доступ — за кредити (тири 1–2) або за CLASH (тири 3–4, ADR-017):

| Тир | Приклади | Платіж | XP/ціна |
|---|---|---|---|
| 1 | пшениця, морква; звичайна деревина, камінь, глина | кредити | базові |
| 2 | томат, гарбуз, соняшник; сосна/дуб, мідь, трави, гриби | кредити | ×3 |
| 3 | clashberry; залізо, рідкісні гриби, ліхтарне масло | CLASH або крафт з тиру 2 | ×10 |
| 4 | кристали печер, сезонні культури | CLASH або лише добування | ×30 |


- Нові предмети: `wood_pine`, `wood_oak`, `ore_copper`, `ore_iron`, `ingot_*` (плавка в майстерні), `herb_*` ×5, `mushroom_*` ×3, `crystal`, `clay`, `tool_axe`, `tool_pickaxe`, `lantern_oil` (з `crop_sunflower` — нова культура на острові); точний список культур і матеріалів дає власник разом з ассетами.
- Куди йдуть: крафт інструментів і їх ремонт; будівництво на острові (нові будівлі: майстерня, комора, теплиця — з матеріалів материка); косметика (одяг персонажа) за кристали; продаж на ринку міста за кредити під той самий денний кап кредитів.
- Нічого не мінтить кредити поза `/market/sell` під капом; CLASH не видається ніде (ADR-017: лише burn + казначейство).
- **Міські кредити** (окремий рахунок у леджі `city_credits`): нараховуються за підтверджені дії у партнерів (стейк ≥ X clashSOL 7 днів, своп ≥ $Y через Jupiter з нашим referral, ліквідність ≥ $Z у пулі 7 днів). Витрачаються на косметику, назви острова, місця в лідерборді сезону — **ніколи не конвертуються в CLASH** (регуляторно й економічно).
- Сезон: 8–12 тижнів, лідерборд за XP + дослідженням + міськими кредитами; нагороди — косметика.

## 7. Місто

Квартали навколо площі:

| Будівля | Що всередині (React-екран над сценою) | Перевірка сервером |
|---|---|---|
| Храм стейкінгу (Sanctum) | стейк SOL → clashSOL через Sanctum SDK у гаманці гравця; показ APY і балансу | читання стейк-рахунку/балансу clashSOL по гаманцю раз на годину (джоба) |
| Обмінник (Jupiter) | своп через Jupiter Terminal/API з platform fee на казначейство | своп-транзакції з нашим referral по гаманцю (джоба або webhook) |
| Фонтан ліквідності (DEX-пул) | депозит у пул CLASH/SOL через SDK DEX | позиція в пулі по гаманцю |
| Ринок | продаж матеріалів за кредити (кап), покупка інструментів/насіння за кредити або CLASH | наявний `/shop`, `/market/sell`, `/orders` |
| Майстерня | крафт інструментів, плавка, ремонт | `/craft` з новими рецептами |
| Ратуша | сезон, лідерборд, щоденні експедиції, щоденник дослідника | нові read-ендпоінти |
| Памʼятники партнерів | «дошка» проєкту: опис, посилання, топ-гравці за міськими кредитами цього проєкту | статика з `settings`/каталогу партнерів |
| Порт | корабель на острів | сцена переходу |

Типи будівель (П3): `partner_api` (функціонал через SDK/API партнера в гаманці гравця), `own_pool` (власні пули та контракти проєкту; окремий ADR на кожен контракт — сервер і далі без ключів), `showcase` (вітрина: порожня споруда, модалка «Упс, цей обʼєкт ще ніким не зайнятий. Можливо, це можете бути Ви або Ваш проєкт» з контактом). Перший реальний партнер — **Sanctum** (LST-токен проєкту вже випущено); Jupiter/DEX і referral/fee — після того, як база з Sanctum протестована.

Партнерське розміщення: партнер платить в USDC → buy & burn CLASH (PLAN). Будівля = запис у таблиці `partners` (id, назва, тип інтеграції, посилання, ліміти), сцена в Godot — з набору 3–4 типових будівель + вивіска.

Вхід у будівлю: `building_entered { building_id }` (уже в протоколі мосту) → React відкриває екран партнера, `set_mode ui`. Вихід — назад на площу.

Демо для показу (2026-09-20): вітрини `showcase_staking`, `showcase_exchange`, `showcase_pools` у dev-збірці або з `?demo=1` відкривають готові екрани на вигаданих даних (`web/src/city/`): храм стейкінгу SOL → clashSOL, обмінник, скарбниця стейблів з власними пулами USDC/USDT і партнерськими інструментами. Це лише вигляд: сервер, гаманець і ланцюг не задіяні, числа не є умовами продукту. Власні пули з дохідністю — рішення, якого ще нема: потрібні джерело доходу, модель ризику й ADR на контракт (інваріант «нуль кастодії» лишається).

## 8. Мультиплеєр (присутність)

За ескізом 2026-09-05, деталізовано:
- **Транспорт**: WebSocket від React-шелу до axum `GET /ws/presence` з тією ж cookie-сесією і CSRF-перевіркою Origin; один сокет на сесію.
- **Клієнт → сервер** 5–10 Гц: `{ t, x, z, yaw, anim, zone }`; сервер перевіряє: зона існує, координати в межах зони, швидкість ≤ 6 м/с (+25 % на дорозі), не частіше 12 повідомлень/с. Порушення — ігнор, після 20 — розрив.
- **Сервер → клієнт** 5 Гц: `peers { [id, nick, x, z, yaw, anim] }` для сусідів у 3 × 3 клітинках по 64 м, ліміт 50 найближчих. Перший пакет — `peers_full`, далі дельти.
- **Кілька інстансів API**: положення в Redis (`presence:<zone>:<cell>` → hash), pub/sub на клітинку. Інстанси без спільного стану в памʼяті.
- **Godot**: `peers_state` через міст → `PeerAvatar` (та сама модель, інтерполяція 100 мс, той самий набір кліпів), нік над головою, без колізій між гравцями.
- **Взаємодії**: подарунок предмета, «помахати», пізніше обмін — через звичайні HTTP-дії з леджем, не через сокет.
- **Ніки** (рішення власника): вільні, з модерацією через адмінку і фільтр слів; якщо на гаманці є доменне імʼя (Solana: `.sol` через SNS/AllDomains; EVM: ENS), беремо його як нік за замовчуванням (джоба читає раз на добу). Гаманець не показується.

## 9. Технічний план клієнта (Godot web, Compatibility)

- **Терен**: висотна карта 1024 × 1024 (1 px = 1 м, `FORMAT_RF`) + карта біомів (RGBA: луки/ліс/скелі/пісок) у `assets/mainland/*.res`, джерело — `client/blender/mainland.blend` і генератор `tools/gen_mainland.py` (див. нижче); чанки 64 м, LOD 0 — крок 2 м з `HeightMapShape3D`, LOD 1 — 8 м. Шейдер `mainland_ground` бере ваги біомів з кольору вершин, схили → камінь, вище 42 м → сніг, берег → мокрий пісок. **Зроблено 2026-09-08** (`MainlandTerrain`, `TerrainChunk`).
- **Гори і посадка обʼєктів (2026-09-09, скриншоти власника)**: рельєф гір печеться окремим шаром 128 × 128 (1 px = 8 м) і масштабується кубічно, тому схили пологі, без голок; усе, що стоїть на терені (вузли, наповнювачі, таблички), сідає на найнижчу точку під своєю основою (`ground_min`), камені/руда нахиляються за нормаллю. Перевірка експорту: після кожного експорту `tools/check_export.gd` проти `web/public/godot/index.pck` (перевіряє й штамп збірки `res://build.txt`, який `addons/build_stamp` кладе в кожен експорт; меню web показує «Клієнт v0.1.0 <дата> <коміт>» — так видно, чи браузер узяв нову збірку) (редактор і експорт — не ті самі дані сцени: перевизначення дочірніх вузлів інстансів губляться, тому параметри будівель — лише властивості кореня `CityBuilding`). Ручне правлення терену (ADR-021, 2026-09-09): джерело — `client/blender/mainland.blend` (обʼєкт `Terrain`, сітка 2 м, Blender Z-up, Y = −Z Godot; кольори вершин = біоми; колекція `Refs` — площа, причал, орієнтири, персонаж 1.8 м, рівень моря). Власник ліпить у Sculpt mode і зберігає файл; далі `blender -b client/blender/mainland.blend --python client/tools/bake_mainland.py` (промені зверху на сітці 1 м → `client/blender/height_1024.f32`) і `godot --headless --path client --script res://tools/import_height.gd` (→ `assets/mainland/height.res`), потім `test_mainland` і рендери. Зворотний шлях з гри у Blender — `tools/dump_height.gd`. Кругообіг перевірено: різниця ≤ 0.01 м. Генератор v2 — `client/tools/gen_mainland.py` (numpy під Python Blender: `blender -b --python …`): фрактальний шум із доменним викривленням, гребені з термічною ерозією, річка з меандрами, змінною шириною, профілем русла, заплавою й піщаними берегами, озеро в улоговині біля пірса, ущелина від водоспаду і дві притоки (сухі яри), болото з озерцями, розмитий берег, дороги причал → місто → міст; пише обидві сирі карти, `build_mainland_blend.py` перезбирає `mainland.blend` (з резервною копією), `import_height.gd` кладе висоти й біоми в гру. Старий GDScript-генератор прибрано; зони `shared/mainland_zones.json` — дані, правляться руками (маски генератора повторюють їх розкладку). Порядок після ліплення власником: більше не запускати генератор і `build_mainland_blend.py`, лише `bake_mainland.py` → `import_height.gd`.
- **Стрімінг**: завантажені чанки в радіусі 3 (7 × 7 = 49 чанків), розпакування по одному за кадр, вивантаження за радіусом 5. Рослинність — MultiMesh на чанк (трава як на острові, дерева інстансами). Бюджет: ≤ 400 draw calls, ≤ 600 K трикутників у кадрі, ≤ 512 МБ памʼяті в браузері.
- **Пропи і вузли ресурсів**: сервер віддає `GET /mainland/chunks?cx&cz&r` → вузли вікна (id, вид, позиція, запас); позиції — детермінована функція сіду світу й таблиці зон `shared/mainland_zones.json` (спільна для сервера й генератора), тому таблиця для них не потрібна — лише для стану (удари/респаун, наступний крок). Godot (`MainlandNodes`/`MainlandNode`) ставить моделі з паку власника `assets/nature/pieces` за `kind` (сосна → `tree_fir_low_less_foliage`, дуб → `tree_oak_regular`, камінь → `stone_average_01`, руда → `stone_big_02`/`stone_big_03_mossy`, трава → `flower_bush_yellow`, гриби → `mushroom_big_brown`/`amanita_red`, очерет → `grass_plain_high_01`, колода → `log_big_regular`; з 2026-09-11, до того — заглушки farm_pack), циліндр-колайдер, рослини прохідні. Дерева-наповнювачі без взаємодії — `MultiMesh` на чанк там, де вага лісу висока. **Зроблено 2026-09-08.** З 2026-09-11 (відео власника: «дерева одне в одному, лука гола») позиції вузлів і всієї флори — один запечений розкид синім шумом: `client/tools/bake_flora.gd` (`godot --headless --path client --script res://tools/bake_flora.gd -- --seed=7 --qa=…png`) бере види `FloraKind` з масиву `flora` вузла `Terrain` (`scenes/mainland/flora/*.tres`, 38 видів у порядку шарів: спершу крони, потім підлісок і трави) і розкидає їх `Scatter` — детермінованим Bridson dart throwing: кандидати на сітці з тремтінням (хеш від сіду, виду й клітинки), приймання за пріоритетом, якщо точка не залазить у суму радіусів (`radius_m`) уже прийнятих — ніщо не росте одне в одному; густота в точці (`tools/flora_field.gd`) = зона з таблиці × мʼякий поріг ваги біому (узлісся рідшає поступово) × кластерний шум FBM (гаї, галявини, плями квітів) × вода/схил/висота × «під кроною» (папороть, гриби, кущі лише поруч із деревами попередніх шарів) × виключення (орієнтири з міграції 0014, дороги й пляж як пісок, місто). Види з `node_kind` стають вузлами ресурсів сервера: стільки на чанк, скільки каже рецепт зони (RECIPE у bake: ліс 6 сосен, 2 дуби, гриб, трава; темний ліс 6 дубів, 2 сосни, мухомор; скелі 4 камені, 2 мідь, залізо; луки 4 трави, дуб, камінь; болото 4 очерети, гриб) — у тих самих точках, що й флора, тому дерево ніколи не росте крізь руду. Результат: `assets/mainland/flora.res` (`FloraBake`: на чанк і вид лише [x, z, yaw, scale]; висоту й нахил чанк добирає сам) і `shared/mainland_nodes.json` (1 127 вузлів; сервер читає таблицю, `id = cx_cz_i` за порядком у чанку). Клієнт (`ChunkFlora`) будує по одному MultiMesh на вид на чанк за виклик (`flora_kinds_per_frame`), дрібне зникає за 30–60 м, у далеких чанках лише дерева й валуни (`far_chunks`); види з `collider_radius_m` (дерева, кущі, валуни, пні, колоди) на чанках LOD 0 отримують циліндри-колайдери — персонаж не проходить крізь них, трави й гриби прохідні. У місті (коло 58 м навколо площі) флора не росте. Листяні дерева й кущі — пак Simple Trees (docs/ASSETS_NATURE.md): три рівні деталізації в одному GLB, `ChunkFlora` бере `lod1_mid` на ближніх чанках і `lod2_far` на далеких через `MainlandTerrain.piece_mesh(scene, hint)`; видів флори 49; тінь крон дає невидима `shadow_crown` (листя тінь від сонця не кидає — мерехтіло), відтінок листя екземпляра задає `FloraKind.tint_*`. Трава материка (з 2026-09-16) — `GrassGpu` у `Mainland.tscn` (`shaders/grass_gpu.gdshader`, форк BinbunGrass): один MultiMesh з одиничними трансформами, а місце, висоту (карта висот терену), дозвіл рости (ваги біомів) і затухання з відстанню кожен пучок рахує сам у вершинному шейдері — нуль роботи CPU, жодних плиток; густота `density` (пучків/м² на високій якості, множиться рівнем `Quality`), радіус `radius_m`, кола без трави `exclusions`. На острові той самі вузол читає маску зайнятості (грядки, стежки, поза формою острова). Вигляд (2026-09-12): усе живе з паку носить `materials/nature_wind_*` (вітер за висотою вершини, фаза від положення екземпляра), під деревами, кущами, валунами й вузлами лежать контактні тіні `ContactShadow` (площини з альфою, заміна SSAO), сонце в `DayCycle` не піднімається вище 52°, тіні мʼякі, серпанок з aerial perspective, колірна корекція градієнтом у `Environment` обох сцен. Зони правляться пензлем (2026-09-16, `addons/flora_paint`): вибрати Terrain у `Mainland.tscn`, у меню 3D-вікна ввімкнути «Малювати», обрати шар (крони / кущі / покрив / деталі — `FloraKind.layer`), мазати по терену (радіус, сила, «стерти»), «Зберегти» → `assets/mainland/flora_paint.png` (512×512, 2 м/px; байт 128 — як є, 0 — нічого, 255 — удвічі), «Запекти» → те саме запікання (`tools/flora_baker.gd`), а `Terrain.editor_preview` показує всю карту з флорою в редакторі; орієнтири, дороги й місто лишаються виключеннями коду. Герой-групи (2026-09-16): ручні композиції `scenes/mainland/groups/*.tscn` (`FloraGroup`: радіус сліду, якір підліску) власник ставить під `Mainland/Groups` як звичайні обʼєкти, дублює й править у редакторі; запікання займає їх кола (флора й вузли не лізуть), у грі `FloraGroups` садить їх на землю. Нові види чи інша густота — правка `.tres` у редакторі + перезапікання; після перепікання рельєфу — теж перезапікання (позиції вузлів зміняться, стан торкнутих вузлів у БД лишиться за старими id). QA-карта одним малюнком показує, де голо, а де густо. Вузли ставляться порціями (4 мс за кадр) і лише в радіусі 2 чанків від персонажа; дані дальших чанків чекають наближення (2026-09-09, після зависань на лісі).
- **Печери**: окремі сцени (`scenes/caves/cave_1.tscn`), вхід = `building_entered`-подібний перехід; світло від ліхтаря гравця (`NightLight` на персонажі).
- **Маршрути**: `NavGrid` на чанк; для довгих шляхів — клік по карті ставить маршрутну точку, перехід між чанками через сусідні сітки.
- **Персонажі інших**: 50 аватарів × ~5 К трикутників = 250 К — у бюджеті; LOD-аватар (без пальців) далі 30 м.
- **Ассети**: farm_pack покриває місто-ферму; для лісу/гір/печер/міста потрібні 2–3 паки в тому ж low-poly стилі (список — окремо, після рішення власника по П1–П4). Стиль вирівнюємо фільтрами, як на острові (AgX, MSAA, віньєтка).
- **Завантаження**: материк — окремий `.pck` (завантажується при вході на корабель), острів лишається малим.

## 10. Сервер

Нові таблиці (окремі міграції, за правилами):
- `mainland_nodes(id, zone, cx, cz, kind, x_dm, z_dm, hits_left, respawn_at, rare bool)` — спільні вузли; `mainland_node_hits(user_id, node_id, day, count)` не потрібна — капи через `rate_events` як зараз.
- `landmarks(id, zone, x_dm, z_dm, reward jsonb)`, `discoveries(user_id, landmark_id, at)`.
- `explored(user_id, chunks bytea)` — 128 байт маски.
- `expeditions(user_id, day, tasks jsonb, done jsonb)`.
- `partners(id, kind, name, links jsonb, enabled)`, `partner_actions(user_id, partner_id, kind, amount, tx_or_ref, at)` — підтверджені дії для міських кредитів.
- Ледж: рахунок `city_credits` (нова `currency`), ті самі правила подвійного запису.

API (ескіз, усе за сесією і з `Idempotency-Key`):
`GET /mainland/chunk/{cx}/{cz}` · `POST /mainland/nodes/{id}/gather` · `POST /mainland/discover` · `GET /mainland/expeditions` · `POST /mainland/expeditions/{n}/claim` · `GET /city/partners` · `POST /city/partners/{id}/verify` (запуск перевірки по гаманцю) · `GET /ws/presence`.

Джоби: респаун вузлів (лінивий, як зараз), генерація рідкісних вузлів по годині, перевірка партнерських дій (RPC-читання), сезонний лідерборд раз на годину.

Безпека: усе з `SECURITY.md` + положення гравця з присутності як умова для `gather`/`discover`; партнерські перевірки лише читають ланцюг; ніяких приватних ключів; будівлі партнерів у CSP `connect-src` лише по allowlist доменів партнерів.

## 13. Ризики

- **Ассети**: low-poly паки для лісу/гір/печер/міста в одному стилі — головна невизначеність по часу і бюджету.
- **Продуктивність web**: 2 × 2 км з рослинністю в Compatibility-рендері без потоків; бюджети в §9 треба підтвердити прототипом терену на M2 раніше за все інше.
- **Партнерські інтеграції**: SDK і умови fee міняються; кожна будівля — окремий ADR з версією SDK.
- **Модерація**: спільний світ без чату знімає більшість ризиків; ніки — єдина точка.
- **Економіка**: матеріали материка не повинні знецінити острів: усе через капи і sinks (інструменти, будівництво); параметри в `settings`, щоб крутити без релізу.
